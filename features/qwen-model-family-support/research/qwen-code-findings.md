# Research: Official Qwen coding harness (qwen-code) — for adding Qwen-family support to the Droxon harness

**Researcher note on tools:** The web extension was verified working (web_search via exa + fetch_content both succeeded); live official sources were fetched and are cited by URL. Pre-seeded files in `features/qwen-model-family-support/research/sources/` are cited by file path. All claims below are OFFICIAL documentation/code unless explicitly marked **[researcher inference]**.

## Summary

qwen-code is Qwen's official open-source coding agent (npm `@qwen-code/qwen-code`), originally forked from Google Gemini CLI v0.8.2 and later independently developed with "customized prompts and function calling protocols" for Qwen3-Coder models. It contains *explicit, name-based model-family detection*: regex matching of model IDs switches the tool-call examples embedded in the system prompt, a DashScope-specific provider layer rewrites thinking knobs per Qwen family (`enable_thinking`, `preserve_thinking`, `thinkingMandatory`), and context windows are inferred "using built-in defaults based on model name matching." Auth today is Alibaba ModelStudio (Coding Plan `sk-sp-` keys, Token Plan, standard DashScope API keys); the Qwen OAuth free tier was discontinued 2026-04-15. For contrast, ZCode (zai-org, GLM's official harness) publicly documents no GLM-specific harness behavior at all — its adaptation is hidden inside a generic provider layer, which is the opposite design point from qwen-code's explicit per-family logic.

## 1. What qwen-code is, what it targets, how users authenticate

1. **Claim:** qwen-code is Qwen's official coding agent for terminal/editor/desktop/web/chat, distributed as npm `@qwen-code/qwen-code`, positioned at feature parity with Claude Code (SubAgents, Agent Teams, Auto-Memory, Auto-Skills, Hooks, MCP, Plan Mode, SDKs). **Sources:** [sources/qwen-code-README.md](../../features/qwen-model-family-support/research/sources/qwen-code-README.md); live: https://github.com/QwenLM/qwen-code. **Support:** direct evidence. **Confidence:** high.
2. **Claim:** Origin — fork of Gemini CLI. The README acknowledges: "This project was originally based on Google Gemini CLI v0.8.2… Starting from Qwen Code v0.1, we stopped syncing with upstream and began independent development as a multi-protocol, multi-platform agent framework." The launch blog states it was "adapted with customized prompts and function calling protocols to fully unleash the capabilities of Qwen3-Coder on agentic coding tasks." **Sources:** [sources/qwen-code-README.md]; https://qwenlm.github.io/blog/qwen3-coder/. **Support:** direct evidence. **Confidence:** high.
3. **Claim:** Models targeted. Through Alibaba Cloud Coding Plan, qwen-code auto-configures: `qwen3.5-plus`, `qwen3.6-plus`, `qwen3.7-plus`, `qwen3-coder-plus` ("Optimized for coding tasks"), `qwen3-coder-next` ("Experimental coding model"), `qwen3-max-2026-01-23`, plus non-Qwen models (`glm-5`, `glm-4.7`, `kimi-k2.5`, `MiniMax-M2.5`). `qwen3-coder-flash` appears as the recommended "fast model" for suggestions/speculative execution. Open-weight targets (self-hosted via Ollama/vLLM): Qwen3-Coder-480B-A35B-Instruct, Qwen3-Coder-30B-A3B-Instruct, Qwen3-Coder-Next (256K native context, 1M with Yarn). **Sources:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/model-providers/ ; https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/ ; https://github.com/QwenLM/Qwen3-Coder/blob/main/README.md. **Support:** direct evidence. **Confidence:** high.
4. **Claim:** Authentication. First-run `/auth` offers: (a) **Alibaba ModelStudio** — Coding Plan (monthly, key prefix `sk-sp-`, endpoint `https://coding.dashscope.aliyuncs.com/v1` CN / `https://coding-intl.dashscope.aliyuncs.com/v1` intl, env `BAILIAN_CODING_PLAN_API_KEY`), Token Plan (usage-based, `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` or Singapore equivalent), or Standard API Key (`DASHSCOPE_API_KEY`, `https://dashscope.aliyuncs.com/compatible-mode/v1`); (b) **Third-party providers** (DeepSeek, Grok, MiniMax, Z.AI, Kimi, ModelScope, OpenRouter, Requesty…); (c) **Custom Provider** (OpenAI/Anthropic/Gemini-compatible, incl. local vLLM/Ollama). **Qwen OAuth free tier was discontinued 2026-04-15**; it remains a hard-coded `qwen-oauth` auth type but is no longer offered in the dialog. All models/providers are declared via `modelProviders` in `~/.qwen/settings.json` and switched at runtime with `/model`. **Sources:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/auth/ ; https://qwenlm.github.io/qwen-code-docs/en/users/configuration/model-providers/. **Support:** direct evidence. **Confidence:** high.

## 2. Model-family handling in qwen-code (detection & per-model behavior)

1. **Claim:** Yes — qwen-code has explicit model detection with behavior switching, in at least four distinct mechanisms:
   - **System-prompt tool-call examples are chosen per model family** by regex on the model ID, in `getToolCallExamples(model?)` (packages/core/src/core/prompts.ts): `/qwen[^-]*-coder/i` (qwen3-coder, qwen2.5-coder, qwen-coder) and `/coder-model/i` → "qwen-coder" XML examples (`<tool_call><function=shell><parameter=command>…</parameter></function></tool_call>`); `/qwen[^-]*-vl/i` → qwen-vl JSON examples; `/gemma[-_]?4/i` → Gemma-4 native; otherwise generic bracket-style examples. An env override `QWEN_CODE_TOOL_CALL_STYLE` (qwen-coder | qwen-vl | gemma4 | general) beats detection. **Source:** https://raw.githubusercontent.com/QwenLM/qwen-code/main/packages/core/src/core/prompts.ts. **Support:** direct evidence (source code). **Confidence:** high.
   - **Context window is inferred by model-name matching:** "Qwen Code determines the context window using built-in defaults based on model name matching, with a constant fallback value" (overridable via `generationConfig.contextWindowSize`). **Source:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/. **Support:** direct evidence. **Confidence:** high.
   - **DashScope/Qwen request-shaping is family-aware.** Documented PR/commit behavior: thinking-disabled side queries emit `extra_body.enable_thinking: false` on DashScope (PR #4505); `preserve_thinking` is default-on for the DashScope provider so prior-turn `reasoning_content` is folded back in for reasoning models like qwen3.6-plus/qwen3.7-max (commit #5637); a `thinkingMandatory` generation-config preset flag marks models (e.g. qwen3.8-max family) that reject `enable_thinking=false` with HTTP 400, and whose thinking mode also rejects `tool_choice: "required"`, so the pipeline drops forced tool selection for them (PR #7303); DashScope requests never carry `tool_choice: "required"` while thinking is active (PR #7661); on the `qwen3.8-max` family an explicit `enable_thinking: false` is translated to the canonical `reasoning_effort: 'none'` — conflicts are resolved "by model family" (PR #8536); on non-DashScope OpenAI-compatible servers, for `qwen*` models the disable switch is sent as `chat_template_kwargs.enable_thinking = false` instead (PR #6271). **Sources:** https://github.com/QwenLM/qwen-code/pull/4505 ; https://github.com/QwenLM/qwen-code/commit/20bfb8eca28aa43a0e29892d28815ffbf0daaf64 ; https://github.com/QwenLM/qwen-code/pull/7303 ; https://github.com/QwenLM/qwen-code/pull/7661 ; https://github.com/QwenLM/qwen-code/pull/8536 ; https://github.com/QwenLM/qwen-code/pull/6271 ; issue https://github.com/QwenLM/qwen-code/issues/7284. **Support:** direct evidence (official repo PRs/commits describing merged behavior). **Confidence:** high.
   - **An "automatic qwen-family gate"** applies to `enableRequestMetadata` for side models (fastModel/compaction/title/subagents): a side model with no explicit setting falls back to this qwen-family gate rather than inheriting the main model's choice. **Source:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/. **Support:** direct evidence. **Confidence:** high.
2. **Claim:** Reasoning controls are protocol/family-aware: `capabilities.reasoning` overrides accept profiles including `openai-effort`, `deepseek-openai`, `dashscope-effort`, `dashscope-thinking`, `qwen-chat-template`, `anthropic-manual`/`anthropic-adaptive`, `gemini`; unknown models must declare profile+efforts+default explicitly, known models inherit from "the provider catalog." A cross-provider `model.reasoningEffort` (low…max) is mapped/clamped per active model/provider. **Sources:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/model-providers/ ; https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/. **Support:** direct evidence. **Confidence:** high.
3. **Claim:** The harness is explicitly multi-model: `fastModel` (e.g. `qwen3-coder-flash`) powers follow-up suggestions, speculative execution, tool-use summaries, session titles/recaps, and memory-relevance selection; `compactionModel`, `visionModel` (vision bridge for text-only mains), `advisorModel`, and `agents.builtin.exploreModel` (selector `inherit` | `fast` | id | `authType:model-id`) partition work across models; `modelFallbacks` (max 3 IDs, e.g. `"qwen-plus,qwen-turbo"`) auto-switch on capacity errors (429/503/529). **Sources:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/ ; https://qwenlm.github.io/qwen-code-docs/en/users/features/followup-suggestions/ ; https://github.com/QwenLM/qwen-code/pull/6273. **Support:** direct evidence. **Confidence:** high.
4. **Claim:** The system prompt itself is Qwen-branded and layered, not per-model beyond tool-call examples: identity "You are Qwen Code, an interactive CLI agent developed by Alibaba Group, specializing in software engineering tasks…", assembled via `assembleSystemPrompt` into stable base / context files / volatile layers, with tool-guidance lines gated by the declared tool surface and full override via `QWEN_SYSTEM_MD` (`.qwen/system.md`). **Source:** https://raw.githubusercontent.com/QwenLM/qwen-code/main/packages/core/src/core/prompts.ts ; PR https://github.com/QwenLM/qwen-code/pull/7707. **Support:** direct evidence. **Confidence:** high.

## 3. Documented characteristics of Qwen coder models a generic harness must adapt to

1. **Claim (output/thinking style):** Qwen3-Coder instruct models (incl. Qwen3-Coder-Next) are **non-thinking-mode only** and "do not generate `<think></think>` blocks in output. Meanwhile, specifying `enable_thinking=False` is no longer required." Contrast: the *plus/plus-tier hosted* models (qwen3.5/3.6/3.7-plus) are configured with `extra_body: {enable_thinking: true}` and thinking-on by default in qwen-code's own presets. **Sources:** https://github.com/QwenLM/Qwen3-Coder/blob/main/README.md ; https://github.com/QwenLM/qwen-code/blob/d40fe7cd/packages/cli/src/constants/codingPlan.ts. **Support:** direct evidence. **Confidence:** high.
2. **Claim (tool calling):** Qwen3-Coder ships a "specially designed function call format"; open-weight serving **requires the new tool parser in SGLang/vLLM** and updated special tokens/tokenizer — serving stack and parser version matter. Hosted qwen3-coder-flash is marketed on "multi-turn tool interaction" and "enhanced tool-calling stability"; qwen3-coder-plus on "excels at tool calling and environment interaction, capable of autonomous programming." Server-side constraint: DashScope rejects `tool_choice: "required"` while thinking is active (which is why qwen-code drops forced tool selection there). **Sources:** https://github.com/QwenLM/Qwen3-Coder/blob/main/README.md ; https://www.alibabacloud.com/help/en/model-studio/qwen3-coder-flash ; https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen3-coder-plus ; https://github.com/QwenLM/qwen-code/pull/7661. **Support:** direct evidence. **Confidence:** high.
3. **Claim (context/output limits):** Open-weight Qwen3-Coder: 256K native, 1M via Yarn. Hosted API: qwen3-coder-plus/flash max input 997,952 tokens (~1M) and max output 65,536; qwen-code presets set `contextWindowSize: 1000000` for coding-plan models. The README's published SWE-bench harness config for `Qwen 3.7 Max`: `temperature=1, top_p=0.95`, adaptive/interleaved thinking at high effort, `context_1m=true`, `max_tokens=64,000`, up to 500 agent iterations. **Sources:** https://github.com/QwenLM/Qwen3-Coder/blob/main/README.md ; https://www.alibabacloud.com/help/en/model-studio/qwen3-coder-flash ; [sources/qwen-code-README.md] (Evaluation section). **Support:** direct evidence. **Confidence:** high.
4. **Claim (prompt adaptation intent):** Qwen's own statement is that qwen-code was adapted — prompts *and* function-calling protocol — specifically for Qwen3-Coder; the current core prompt leans on precise instruction-following conventions (verify via project commands, never claim success without verification, avoid unrequested features, prefer dedicated tools, parallelize independent calls), i.e., harness discipline rather than model-flavored prose. Output styles (Concise/Proactive/Explanatory/Learning) are a user setting layered on top. **Sources:** https://qwenlm.github.io/blog/qwen3-coder/ ; prompts.ts (above). **Support:** direct evidence; the "harness discipline" characterization is **[researcher inference]** from the prompt text. **Confidence:** medium (inference part).
5. **Claim (serving/protocol quirk):** For legacy OpenAI-compatible runtimes whose tool templates ignore text content parts (e.g. "older GLM-5.1 vLLM/SGLang templates"), qwen-code offers `toolResultContentFormat: "string"` — evidence that even the Qwen harness carries cross-family serialization knobs, and that Qwen's default is the standard content-parts shape. **Source:** https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/. **Support:** direct evidence. **Confidence:** high.

## 4. Contrast: zai-org/ZCode (GLM's official harness)

1. **Claim:** ZCode is Z.ai's (zai-org) AI coding workbench — desktop (Electron), browser UI, and a terminal agent behind one `zcode` command (TUI / `--web` / agent CLI); current version v3.14.3 (2026-9-23 update). The public README is entirely about build/packaging/dev workflow: pnpm bootstrap, Electron bundling, CLI distribution, repo layout (`packages/provider`, `packages/provider-node` for provider capability, `apps/zcode-cli` for the agent). **Sources:** [sources/zcode-README.md]; live https://raw.githubusercontent.com/zai-org/ZCode/main/README.en.md. **Support:** direct evidence. **Confidence:** high.
2. **Claim:** Per its README, ZCode documents **no GLM-specific prompt, thinking-knob, or behavior adaptation at all.** Model/provider handling is abstracted behind a provider layer plus a replaceable built-in provider config (`ZCODE_BUILTIN_PROVIDER_CONFIG_FILE`); the shipped `config/default.json` contains only feedback/community URLs (verified by fetching it — no model data). The zcode-cli README covers plugins/hooks/MCP generically, with no model-family logic. **Sources:** [sources/zcode-README.md]; https://raw.githubusercontent.com/zai-org/ZCode/main/README.en.md ; https://raw.githubusercontent.com/zai-org/ZCode/main/config/README.md ; https://raw.githubusercontent.com/zai-org/ZCode/main/config/default.json ; https://raw.githubusercontent.com/zai-org/ZCode/main/apps/zcode-cli/README.md. **Support:** direct evidence. **Confidence:** high.
3. **[researcher inference]** ZCode's GLM tuning is real but *private* — baked into the product/provider implementations rather than documented, which is why qwen-code's Coding Plan can list `glm-5`/`glm-4.7` as plain OpenAI-compatible entries with `enable_thinking: true`. A generic harness speaking to GLM through standard endpoints mainly needs: the right endpoint/base URL, thinking enabled via the family's knob, and (per qwen-code's own compat flag) `toolResultContentFormat: "string"` against older GLM vLLM/SGLang templates. **Confidence:** medium. **Support:** interpretation of the above sources.

## Contradictions

- **Qwen OAuth free tier:** the task framing (and all pre-2026 material) describes a free Qwen OAuth tier (historically ~2,000 requests/day); current official docs state it was **discontinued 2026-04-15** and removed from the `/auth` dialog while remaining a hard-coded legacy auth type. Treat OAuth as dead; build on ModelStudio keys. (https://qwenlm.github.io/qwen-code-docs/en/users/configuration/auth/)
- **qwen3-coder-flash availability:** it is documented as a first-class fast-model example and hosted Model Studio model, but it is *not* in the current Coding Plan auto-configured model list (which has plus/next/max tiers). No contradiction in sources, but worth noting flash is configured via Model Studio / manual entries rather than the Coding Plan preset. (settings + model-providers docs)
- **Context-based plus↔flash auto-switching:** older qwen-code versions (2025) documented automatic switching between qwen3-coder-plus and qwen3-coder-flash by context length. Current main documents `modelFallbacks` (capacity-error-driven, explicit list) and `fastModel` instead; I found no current-doc evidence of automatic context-length switching. Treat it as a legacy behavior, not a pattern to copy.

## Actionable implications for the Droxon harness (GLM-tuned → Qwen-aware)

**[researcher inference throughout this section — design synthesis from the official evidence above]**

1. **Detection = model-ID patterns + endpoint, not auth type.** Detect Qwen via `/qwen/i` prefixes and especially `/qwen[^-]*-coder/i` for coder models (mirroring qwen-code), plus DashScope/ModelStudio endpoints (`dashscope.aliyuncs.com`, `coding.dashscope.aliyuncs.com`, `*.maas.aliyuncs.com`). Keep it data-driven: qwen-code itself migrated hard-coded model gates (qwen3.8) into preset flags (`thinkingMandatory`) after they broke.
2. **Request shaping switches per family.** For Qwen on DashScope wire: thinking via `extra_body.enable_thinking` (on for plus/max tiers, off/irrelevant for open-weight Coder instruct models), `extra_body.preserve_thinking: true` for multi-turn reasoning continuity, never `tool_choice: "required"` while thinking is on, translate `enable_thinking:false` → `reasoning_effort:'none'` on thinking-mandatory families; on non-DashScope OpenAI-compatible servers use `chat_template_kwargs.enable_thinking:false`. This is exactly where a GLM-tuned harness will mis-fire today (GLM and Qwen disagree on where the thinking knob lives and which combos are rejected with 400s).
3. **Prompt layer changes when model is Qwen:** swap tool-call *examples* to the Qwen coder XML format (`<tool_call><function=name><parameter=…>…`); keep the discipline text (verify-then-report, no unrequested features) which qwen-code shows works for Qwen coder models; for open-weight Qwen3-Coder don't expect/require `<think>` handling, for hosted plus/max tiers do. Ensure tool-result serialization uses standard content-parts (with a `string` fallback for old templates).
4. **Config/auth presets:** ship Qwen presets for (a) Model Studio API key: `DASHSCOPE_API_KEY` + `https://dashscope.aliyuncs.com/compatible-mode/v1`; (b) Coding Plan: `sk-sp-` key + `https://coding.dashscope.aliyuncs.com/v1` (CN) / `coding-intl…` (intl); (c) Token Plan endpoints; set context window ~1,000,000 and max output 65,536 for coder-plus/flash; do not build on Qwen OAuth (dead).
5. **Harness structure worth copying:** a fast side-model slot (qwen3-coder-flash for titles/suggestions/tool-summaries/memory ranking), an ordered fallback chain on 429/503/529, capability/limit inference from model name with per-entry overrides, and a family-gated side-query policy (side queries think-disabled unless the model forbids it). Symmetrically, keep the existing GLM profile as another preset: GLM's public surface is just provider config + `enable_thinking`-style flags (ZCode exposes nothing special), so both families should live behind one "model family intelligence" preset table.
6. **What NOT to copy:** qwen-code's OAuth-centric onboarding (deprecated), and its Claude-Code-parity breadth (SubAgents/Arena/desktop) is orthogonal to family intelligence.
